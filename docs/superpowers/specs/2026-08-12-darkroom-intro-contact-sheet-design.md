# 暗房進場畫面重新設計：「接觸印樣」

日期：2026-08-12 ／ 狀態：待使用者確認

## 背景

暗房的進場畫面已經換過三代（跑馬燈 → 無限畫布 → 顯影盤）。前兩代因為次像素重新
取樣而閃爍，追了四輪都沒解決；第三代「顯影盤」把整個場景改成單一片段著色器，技術
上站得住，但**視覺方向是材質擬真**（顆粒、暖色相紙、化學感），使用者要的是**現代
簡約 ＋ 效果驚奇**。方向不對，重做。

## 設計方向

**接觸印樣 × 放大鏡。**

近乎全黑的畫面上鋪著整片詞庫的接觸印樣，暗到幾乎看不見——只剩網格的暗示。游標帶
著一片真正的光學玻璃：它底下的印樣變得銳利、明亮、放大，而且帶著真實鏡片的桶形
畸變與邊緣色散。

**為什麼是這個**

- **現代簡約**：畫面上實質只有四樣東西——黑、一個圓、一條髮絲鏡框、琥珀 accent。
  沒有材質、沒有顆粒、沒有裝飾。
- **驚奇**：反差。看起來空無一物的黑，跟著你的手裂開一扇明亮的窗；而且那不是 CSS
  遮罩，是真的在做光學運算（放大、桶形畸變、RGB 色散、鏡片漸暈）。
- **是這個工具的語言**：拿放大鏡看接觸印樣本來就是暗房的動作，鏡片跟品牌的光圈
  logo 同一個家族。三個候選方案裡，**只有這個把使用者真正的內容（兩萬多張詞庫圖）
  當主角**——另外兩案把圖丟到失焦背景或只透出筆畫。

## 視覺規格

| 元素 | 規格 |
|------|------|
| 底色 | `#08090d`（比面板 `--bg` 更暗，讓印樣有得亮） |
| 接觸印樣 | 8 欄 × 5 列 = 40 張詞庫縮圖，cover 鋪滿視窗 |
| 印樣亮度 | 約 5%，並帶極淡琥珀染色——「看得出有東西，但讀不出是什麼」 |
| 放大鏡半徑 | 視窗高度的 15.5% |
| 放大倍率 | 2.0× |
| 桶形畸變 | 邊緣壓縮係數 0.30 ×（r/R)²，凸透鏡的實際行為 |
| 色散 | RGB 三通道以不同放大率取樣，強度 ∝ (r/R)²，中心為 0 |
| 鏡片漸暈 | 內側邊緣壓暗 22%，真實鏡片的自然衰減 |
| 鏡框 | 1px 琥珀髮絲線 ＋ 極窄柔光暈 |
| 整體暗角 | 有，收斂視線 |

## 互動規格

| 行為 | 規格 |
|------|------|
| 跟隨 | 彈簧跟隨游標，略慢半拍——玻璃有重量，不是黏在指標上 |
| 閒置 | 停止操作 2.2 秒後，鏡片沿緩慢 Lissajous 路徑自己漂移 |
| 回手 | 游標再動時平順接管，不跳位 |
| 觸控 | 拖曳等同滑動 |
| 減少動態 | 不跑迴圈，靜態一幀、鏡片置中 |
| 關閉 | 「進入」鈕／`Enter`／`Esc` |

## 技術規格

- **單一全螢幕片段著色器，原生 WebGL、零依賴。** 不動 `STATIC_FILES`、不用重啟
  伺服器（只重整頁面即可）。
- **印樣是一張 atlas 貼圖**：40 張縮圖畫進一張 2D canvas（每格 256px → 2048×1280），
  上傳成單一材質，全畫面只要一次 draw call。縮圖到齊一張就重畫並重新上傳一次
  （漸進顯影，不必等全部載完）。`w=256` 正好命中後端既有的尺寸級距，不用改後端。
- 啟動時檢查 `MAX_TEXTURE_SIZE`，不足就自動降成 6×4 / 192px 的較小 atlas。
- DPR 夾在 1.5（整片著色器的成本與像素數成正比）。
- **沿用已驗證過的骨架**：`introInitGL` / `introResize` / `introFrame` / `closeIntro`，
  並保留兩條已經踩過的教訓——uniform 每次都寫（uniform 屬於 program、畫布尺寸屬於
  元素），以及 `pointermove` 裡絕不量幾何（矩形快取在 resize 時更新）。
- 關閉時釋放材質與 program 並 `loseContext()`。

**退化路徑**

| 情況 | 行為 |
|------|------|
| 拿不到 WebGL | DOM 版：印樣網格 ＋ 跟著游標的 CSS 徑向高光 |
| 減少動態 | 走退化版、不跑迴圈 |
| 縮圖載入失敗 | 該格留空（底色），不影響其餘 |

## 要移除的東西

「顯影盤」的整段著色器與流程：顯影前緣、銀鹽顆粒、漣漪系統（`introAgit`／
`INTRO_RIPPLE_*`）、相位機（develop/hold/lift/settle）、`introBlurFor`。

## 風險與對策

| 風險 | 對策 |
|------|------|
| 靜止時畫面看起來像空的／壞的 | 閒置漂移＋印樣「暗但存在」＋題字與按鈕永遠可見 |
| 放大後印樣糊掉 | 每格 256px 來源、螢幕上每格約 160px，放大 2× 後 320px vs 來源 256px（比值 0.8，足夠銳利） |
| 40 個縮圖請求 | 每張只有 256px（比舊版無限畫布的 81 張輕），`fetchPriority: low` |
| 又出現閃爍 | 這個設計裡沒有任何東西持續做次像素位移——印樣是靜止的，只有鏡片在動，而鏡片是著色器內的座標運算、不是圖層搬移 |

## 驗收標準

1. vertex／fragment／link 全部編譯通過（在瀏覽器裡實測，不是只看有沒有畫面）
2. 鏡片內像素明顯亮於鏡片外（讀 `readPixels` 比對）
3. 鏡片邊緣有 RGB 分離（讀邊緣像素，R/B 通道值不同）
4. 移動游標會改變鏡片位置；閒置後鏡片仍在移動
5. 停用 WebGL 時退化版正常顯示
6. 關閉後 `introGL`／`introRAF` 皆為 `null`
7. 載入零失敗請求、console 無錯誤
